# Documentation

Use for standalone technical documentation, reports, PR descriptions,
architecture summaries, stakeholder updates, and runbooks.

For standalone output, write directly without an approval gate. Do not modify
repository files in this workflow.

Editing documentation stored in the repository is IMPLEMENTATION. Outside LOOP,
obtain implementation plan approval first; inside LOOP, its initial
authorization covers in-scope edits.

Identify the audience, purpose, evidence, assumptions, limits, and required
format. Write clearly and use repository terminology. Separate facts,
observations, interpretations, and recommendations; avoid unsupported claims or
marketing language.

Technical documentation should cover context, design, implementation details,
operational considerations, and known limits as relevant. Experiment reports
should cover objective, hypothesis, method, inputs, metrics, results, baseline,
conclusion, and next steps. Finish with key findings, risks, and open questions.
